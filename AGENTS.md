# F-Type-OpenCluster

Prioritize owner-authored changes to the factory interface loaded from an ordinary USB flash drive on the MY2015 US F-TYPE S Coupé. Either original display qualifies. Record the module version, installation steps and visible change on the physical screen before describing a package as vehicle-tested. Treat the desktop preview as a reference. Media playback, navigation markers and phone-hosted apps do not establish USB customization of the factory interface.

Keep model year, market, module, and evidence source attached to each vehicle-specific observation. A part-catalog entry, a local file digest, and a vehicle identification record answer different questions. Record which one supports each claim.

For first-generation F-TYPE research, use published documentation, local file inventory and original desktop display models. Keep OEM files and diagnostic exports under the ignored firmware/ and private/ directories. Publish original tools, synthetic fixtures, public part numbers and reproducible research notes.

The lead may create and revise project-specific roles under .codex/agents/ and select the model and reasoning effort for each independent task. Use the available lighter models for catalog work and source transcription. Use deeper reasoning when evidence conflicts. When delegating, check the model and effort if the client exposes them. Keep roles only while they have a distinct job.

Run the README test command after changes to the inventory tool. Update the research note when a finding changes the evidence for a specific model year.
